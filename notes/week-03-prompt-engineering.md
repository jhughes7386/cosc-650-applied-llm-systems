# Week 3 — Prompt Engineering

## The Anatomy of a Prompt

* [The Anatomy of a Prompt](https://craigtrim.com/articles/prompt-anatomy/) — system prompts, user prompts, few-shot examples, and chain-of-thought scaffolding as composable structural components.

## The Prompt Engineer's Pattern Books

* [The Prompt Engineer's Pattern Books](https://craigtrim.com/articles/prompt-patterns/) — reusable patterns that can solve common prompting problems, including persona, template, meta-prompting, and self-consistency, and how to recognize which pattern fits a problem.

## Prompts Are Code

* [Prompts Are Code](https://craigtrim.com/articles/prompts-are-code/) — version control workflows for prompts, building test suites with evaluation metrics, regression detection across model updates, and the case for prompt CI/CD.

## When Prompts Fail: A Debugging Field Guide

* [When Prompts Fail: A Debugging Field Guide](https://craigtrim.com/articles/when-prompts-fail/) — common failure modes such as hallucination, refusal, instruction drift, format non-compliance, and prompt injection. It also covers ways to diagnose these problems and make targeted fixes.

## How NOT to Write a Prompt

* [How NOT to Write a Prompt](https://craigtrim.com/articles/how-not-to-write-a-prompt/) — common prompting mistakes such as vague requests, missing examples, overly complicated prompts, skipping system prompts, trusting untrusted input, and using an LLM when another solution would work better.

## When to Prompt, When to Code, When to Train

* [When to Prompt, When to Code, When to Train](https://craigtrim.com/articles/when-to-prompt-code-train/) — a decision framework for choosing between writing code, prompting, using a hybrid approach, prompt-to-train-to-distill, or embed-to-classify. It also considers task properties such as latency, error cost, and volume.
